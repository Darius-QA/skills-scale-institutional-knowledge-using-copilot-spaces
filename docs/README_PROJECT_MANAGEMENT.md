# OctoAcme Project Management Docs

This README provides a short summary of OctoAcme's project management processes and direct links to the full process documents in this repository's `docs/` folder.

## Summary

OctoAcme follows an iterative, customer-first approach with clear roles, defined artifacts, and a structured project lifecycle. Our approach emphasizes:

- **Customer-first focus**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments and gather feedback early
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead (PdM)
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and continuous improvement

### Core Roles

- **Project Manager (PM)**: Coordinates delivery, schedules, risk management, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs and approvals

### Project Lifecycle

1. **Initiation**: Define problem statement, identify stakeholders, establish high-level timeline
2. **Planning**: Break work into shippable increments, identify dependencies and risks, align timelines
3. **Execution**: Build, test, review, and iterate on features
4. **Release**: Deploy to production, verify, and announce to stakeholders
5. **Retrospective**: Capture learnings and convert them into actionable improvements

### Team Cadence

- **Daily standups** (15 min): Focus on progress, blockers, and dependencies
- **Weekly delivery sync**: Review progress, updates, and flagged risks
- **Sprint/milestone demos**: Show completed work to stakeholders and gather feedback
- **Monthly stakeholder updates**: Share progress and align on priorities
- **Ad-hoc escalations**: Address urgent issues and cross-team dependencies

## Key Artifacts

- **Project One-pager**: Problem statement, goals, success metrics, stakeholders, timeline, risks
- **Roadmap & Release Plan**: Prioritized features mapped to releases and milestones
- **Sprint/Iteration Backlog**: Prioritized list of work items with acceptance criteria and estimates
- **Risk Register**: Tracked risks with impact, likelihood, owner, and mitigation plans
- **Retrospective Notes**: Learnings and action items for continuous improvement

## How to Use This Documentation

### For New Team Members
1. Start here to understand OctoAcme's approach
2. Read the **Project Management Overview** for a comprehensive introduction
3. Refer to specific documents based on your role (e.g., PMs read Initiation & Planning; Developers read Execution)

### For Project Leads
1. Open the **Project One-pager template** in the Project Initiation doc when starting a new initiative
2. Use the **Project Planning** doc to create a prioritized backlog and release plan
3. Keep the **Risk Register** updated throughout execution
4. Surface major blockers and risks in the weekly PM + PdM sync

### For Execution & Delivery
1. Use **Execution & Tracking** to set up your team's daily cadence and quality standards
2. Maintain a **Definition of Done** and clear acceptance criteria for all work
3. Escalate blockers using the defined escalation paths in **Risk Management & Communication**
4. Run retrospectives at the end of each sprint or milestone using the **Retrospective** doc template

### For Releases
1. Follow the **Release & Deployment** checklist before going to production
2. Use the **Release Notes template** to communicate changes to stakeholders
3. Have a rollback plan ready and follow the incident playbook if issues arise
